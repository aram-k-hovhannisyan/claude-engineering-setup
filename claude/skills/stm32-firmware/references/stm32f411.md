# STM32F411 profile

Reference profile for STM32F411 work; no exact part, board or project is assumed. Clarify the complete part/package, board revision, supply/debug interface, oscillator source/frequency, pin assignments and firmware/boot requirements when a project begins. Derive these from available board/project files before asking for missing decisions.

Use that variant's datasheet, reference manual and errata to establish flash/RAM, startup, vector placement, peripheral instances and alternate functions. Do not assume a Nucleo/Discovery board, LED pin, external clock, flash size, bootloader layout or another STM32 family's features. Verify Cortex-M4 FPU/ABI against the selected compiler settings; do not apply M7 data-cache recipes by analogy.

Check clock-tree/APB timer behavior, DMA request/stream/channel compatibility and buffer placement using the actual manual and generated project. Bare metal is the default. The user explicitly chooses any OS; interrupt priorities and middleware ownership must then be coordinated with it.

For first validation, compile a minimal agreed project before programming. A hardware smoke test uses a known observable signal or RAM signature and the exact identified probe/device; do not invent board wiring.
